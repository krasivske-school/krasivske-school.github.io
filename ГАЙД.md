# Гайд по сайту: що де лежить і як змінити

Сайт: **https://krasivske-school.github.io**
Адмінка: **https://krasivske-school.github.io/admin/**

---

## 1. Два способи щось змінити

| Спосіб | Коли | Складність |
|---|---|---|
| **Адмінка** | новини, документи, тексти сторінок, контакти, цифри на головній | легко, з браузера, з будь-якого пристрою |
| **Вручну у файлах** | те, чого немає в адмінці: кнопки на головній, меню, кольори, вигляд | треба відкрити файл у редакторі |

Усе, що можна зробити в адмінці, краще робити там: вона не дасть зламати файл.

---

## 2. Порядок роботи вручну (завжди однаковий)

1. Відкрийте **GitHub Desktop**.
2. Натисніть **Fetch origin**, потім **Pull origin** (якщо з'явиться). Так ви підтягнете зміни з адмінки.
3. Змініть файл (у Блокноті, VS Code або будь-якому редакторі тексту).
4. У GitHub Desktop внизу ліворуч напишіть, що змінили, наприклад `Новий телефон`.
5. **Commit to main** → **Push origin**.
6. Через 1–2 хвилини зміни на сайті. Хід публікації видно на github.com → репозиторій → вкладка **Actions** (зелена галочка — все добре, червоний хрестик — помилка, див. розділ 9).

> Файли відкривайте редактором тексту, **не Word**. Word псує файли.
> Зручно встановити безкоштовний **VS Code** (code.visualstudio.com): він підсвічує помилки.

│  ├─ data/
│  │  ├─ site.json         ← назва, контакти, цифри на головній, адміністрація, гарячі лінії
│  │  └─ documents.json    ← список документів
│  ├─ content/
│  │  ├─ news/             ← новини, кожна — окремий файл .md
│  │  └─ pages/            ← текстові сторінки (історія, вступ, булінг, структура…)
│  ├─ pages/
│  │  ├─ index.astro       ← головна сторінка (кнопки «Швидкий доступ», фото)
│  │  └─ kontakty.astro    ← сторінка «Контакти»
│  ├─ layouts/Base.astro   ← шапка і підвал сайту (на всіх сторінках)
│  ├─ lib/nav.ts           ← пункти меню
│  └─ styles/global.css    ← кольори, шрифти, вигляд
├─ public/
│  ├─ uploads/             ← фото і файли (PDF, Word)
│  └─ admin/config.yml     ← налаштування адмінки (які поля є)

Решту файлів і папок (`node_modules`, `dist`, `.github`, `scripts`, `astro.config.mjs`, `package.json`) **не чіпайте**.

## 4. Найчастіші ручні зміни

### Назва закладу, підпис, цифри на головній
Файл **`src/data/site.json`** (або в адмінці: Документи і контакти → Контакти і загальна інформація).

```json
"name": "Красівський ліцей",
"fullName": "Красівський ліцей Новопільської сільської ради",
"tagline": "Заклад загальної середньої освіти · с. Красівське",
"facts": [
  { "value": "256", "label": "учнів" },
  ...
]
```
Коли заклад стане гімназією — змініть `name` і `fullName`, решта сайту підлаштується сама.

### Телефон, e-mail, адреса, мапа, Facebook
Там само, блок `"contacts"`. Посилання на мапу з точними координатами:
`https://www.google.com/maps/search/?api=1&query=ШИРОТА,ДОВГОТА`

### Адміністрація
`site.json`, блок `"administration"`. Кожна людина — один рядок `{ ... }`.

### Кнопки «Швидкий доступ» на головній
Файл **`src/pages/index.astro`**, на початку:
```js
const quick = [
  { title: 'Вступ до 1 класу', text: 'Документи, заява і строки зарахування', href: '/batkam/vstup-do-1-klasu/' },
  ...
];
```
`title` — заголовок картки, `text` — підпис, `href` — куди веде. Адресу сторінки візьміть з браузера (частина після `.github.io`).

### Фото на головній
Покладіть нове фото в `public/uploads/`, наприклад `shkola-2027.jpg`, і в `src/pages/index.astro` змініть
`url('/uploads/shkola.jpg')` на `url('/uploads/shkola-2027.jpg')`. Найкраще — широке фото, приблизно 1600×880, до 500 КБ.

### Картинка в шапці біля назви
`site.json` → `"logo"`. Квадратне фото, 200×200 пікселів.

### Пункти меню
Файл **`src/lib/nav.ts`** → список `sections`. Тут можна змінити назву пункту (`title`) і опис розділу (`description`).
`id` — це адреса розділу, його краще не міняти, інакше старі посилання перестануть працювати.

### Текст на сторінці
Файл у **`src/content/pages/`**. Вгорі між `---` — налаштування сторінки, нижче — текст.

| Що | Як записати |
|---|---|
| Заголовок | `## Заголовок` |
| Жирний | `**жирний**` |
| Список | рядок починається з `- ` або `1. ` |
| Посилання | `[текст](https://адреса)` |
| Картинка | `![опис](/uploads/foto.jpg)` |
| Новий абзац | порожній рядок між абзацами |

### Нова сторінка
Скопіюйте будь-який файл у `src/content/pages/`, перейменуйте латиницею без пробілів (`nova-storinka.md`)
і змініть верх:
```
---
section: "batkam"        ← розділ: pro-nas, batkam або dokumenty
group: "Корисне"         ← підзаголовок у розділі (необов'язково)
title: "Назва сторінки"
order: 100               ← місце у списку: менше число — вище
description: "Короткий опис для картки"
---
```
Сторінка з'явиться в розділі сама. Простіше — через адмінку: Сторінки → Створити.

### Документи — див. окремий розділ 5 нижче

### Кольори
Файл **`src/styles/global.css`**, на самому початку:
```css
--bg: #ffffff;      ← тло
--bg-soft: #f2f3f5; ← сірі картки
--ink: #000000;     ← текст і чорні кнопки
--link: #1650c8;    ← колір посилань у текстах
--grad: ...         ← пастельний градієнт у шапках сторінок
```
Нижче такий самий блок — для темної теми.

## 5. Документи: файл, посилання на Google, текст

На сторінці «Документи» бувають три види записів:

| Що | Як виглядає на сайті | Де лежить |
|---|---|---|
| **Документ-файл** (PDF, Word) | рядок у списку, відкриває файл | `public/uploads/` + рядок у `src/data/documents.json` |
| **Документ-посилання на Google** | такий самий рядок, відкриває Google Docs / Drive | рядок у `src/data/documents.json` |
| **Документ-текст** (наприклад «Розмір плати за навчання») | кнопка вгорі сторінки «Документи», відкриває сторінку з текстом | файл у `src/content/pages/` з `section: "dokumenty"` |

### 5.1. Спершу відкрийте доступ у Google

Без цього відвідувачі побачать «Немає доступу».
1. Відкрийте документ у Google Docs або файл у Google Drive.
2. **Поділитися** (Share) → **Загальний доступ** → **Усі, хто має посилання**.
3. Роль — **Читач** (Viewer). Не «Редактор»!
4. **Копіювати посилання** → **Готово**.

Перевірка: відкрийте посилання в режимі інкогніто (Ctrl + Shift + N). Якщо документ видно без входу — все правильно.

### 5.2. Додати документ-посилання на Google

**Через адмінку (простіше):** Документи і контакти → Документи → **Додати документ** →
назва, категорія, рік → поле **«Або посилання»** → вставте посилання → Зберегти. Поле «Файл» лишіть порожнім.

**Вручну:** файл `src/data/documents.json`, у список `"documents"` додайте рядок:
```json
{ "title": "Кошторис на 2027 рік", "category": "zvitnist", "year": "2027", "url": "https://drive.google.com/file/d/.../view" },
```
Сайт сам підпише його «Google Docs» або «Google Drive» і відкриватиме в новій вкладці.

### 5.3. Додати документ-файл (PDF, Word)

**Через адмінку:** те саме, але в поле **«Файл»** завантажте PDF.

**Вручну:** покладіть файл у `public/uploads/` (назва латиницею без пробілів, наприклад `statut-2027.pdf`) і додайте рядок:
```json
{ "title": "Статут (нова редакція)", "category": "ustanovchi", "year": "2027", "file": "/uploads/statut-2027.pdf" },
```

Якщо в рядку є і `file`, і `url` — відкривається `file`.

**Коди категорій** (поле `category`):

| Код | Категорія |
|---|---|
| `ustanovchi` | Установчі документи |
| `litsenzuvannia` | Ліцензування |
| `osvitni-prohramy` | Освітні програми |
| `zvitnist` | Звітність і фінанси |
| `atestatsiia` | Атестація педагогів |
| `pidruchnyky` | Вибір підручників |
| `bezpeka` | Безпека і протидія булінгу |
| `batkam` | Для батьків |

Документ, що застарів, просто видаліть рядок (і файл з `public/uploads/`, якщо був).

### 5.4. Додати документ-текст (сторінку з текстом і посиланнями)

Коли документ — це кілька абзаців тексту, а не файл. Наприклад, «Правила прийому» чи «Розмір плати за навчання».

**Через адмінку:** Сторінки → **Створити** → розділ **Документи** → назва, короткий опис, текст → Зберегти.

**Вручну:** створіть файл у `src/content/pages/`, наприклад `poriadok-zvernen.md`:
```
---
section: "dokumenty"
title: "Порядок розгляду звернень"
order: 30
description: "Як подати звернення до закладу і в які строки його розглядають"
---

Звернення приймаються письмово або на e-mail закладу.

## Строки розгляду

1. До 15 днів — якщо не потрібна додаткова перевірка.
2. До 30 днів — в інших випадках.

Повний текст: [Порядок розгляду звернень (Google Docs)](https://docs.google.com/document/d/.../edit)
```
Посилання записується так: `[текст, який видно](адреса)`. Посилання на Google відкриються в новій вкладці самі.

### 5.5. Додати текст з посиланням на Google на будь-яку сторінку

Відкрийте сторінку в адмінці (Сторінки → потрібна) або файл у `src/content/pages/` і допишіть у потрібне місце:
```
Детальніше — у [плані заходів на 2026/2027 н. р.](https://docs.google.com/document/d/.../edit).
```
Список документів на сторінці:
```
## Документи

- [Зразок заяви](https://drive.google.com/file/d/.../view)
- [Порядок реагування](https://docs.google.com/document/d/.../edit)
```

## 6. Правила для JSON-файлів (`site.json`, `documents.json`)

Це найчастіша причина поломок:
- Текст — завжди в **подвійних лапках** `"..."`.
- Між рядками списку — **кома**. Після **останнього** рядка коми **немає**.
- Дужки `{ }` і `[ ]` мають бути в парі.
- Лапки всередині тексту пишіть «ялинками» (`«Подвиг»`), а не `"`.

Перевірити файл можна на сайті **jsonlint.com**: вставте вміст → Validate.

## 7. Фото і файли

- Фото кладіть у `public/uploads/`. Назви — латиницею, без пробілів: `osinnii-bal-2026.jpg`.
- Через адмінку фото стискаються автоматично. Вручну — зменшіть перед завантаженням (сервіс **squoosh.app**), бажано до 500 КБ.
- Відео — тільки посиланням на YouTube.
- Великі PDF-скани стискайте (ilovepdf.com → Compress PDF).

## 8. Чого не можна класти на сайт

Сайт і репозиторій **відкриті для всіх**, і GitHub пам'ятає навіть видалені файли:
- списки учнів з датами народження, адресами, телефонами;
- паспортні дані, ІПН, медичні довідки;
- заяви батьків, особові справи.

Фото дітей — лише за згодою батьків, без повних імен під фото.

## 9. Якщо щось пішло не так

| Проблема | Що робити |
|---|---|
| На вкладці **Actions** червоний хрестик | Відкрийте його → червоний крок → внизу текст помилки. Найчастіше — кома чи лапка в JSON (розділ 6). Виправте файл і знову Commit → Push. |
| GitHub Desktop: «Newer commits on remote» | Натисніть **Fetch**, потім **Pull origin**, потім **Push origin**. |
| GitHub Desktop: конфлікт файлів | Нічого не натискайте, зверніться по допомогу (Claude / розробник). |
| Зміни не видно на сайті | Зачекайте 2 хвилини, оновіть сторінку з **Ctrl + F5**. |
| Хочу скасувати останню зміну | GitHub Desktop → вкладка **History** → правою кнопкою на зміні → **Revert changes in commit** → Push. |
